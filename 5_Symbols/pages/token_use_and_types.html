💡 Why Prompt Caching Matters

Prompt Caching allows users to flag static context (such as system instructions, document repositories, or multi-turn agent conversation history) to prevent Claude from re-processing the same tokens repeatedly. Cache hits represent a massive shift in performance and cost.

  • 90% Cost Reduction: While standard input tokens cost $3.00 per million (on Claude 3.5 Sonnet), reading cached tokens only costs $0.30 per million.
  • Latency Optimization: Pre-processed tokens skip the LLM evaluation phase, cutting Time-to-First-Token (TTFT) by up to 2x - 10x. This is critical for real-time chat widgets and fast agent execution loops.
  • Caching Mechanics: Elements must be marked with "type": "ephemeral" in the API payload. Cache lasts 5 minutes and is refreshed automatically on any hit. Minimum cache sizes apply (e.g., 1,000 tokens for Sonnet/Opus).

⚠️ Why Input Tokens Could Be a Bottleneck

Relying solely on packing information into the prompt context creates systemic architectural bottlenecks:

  • Linear Scaling Costs: In multi-turn agent loops (such as Claude Code or software development loops), sending the entire file collection in each turn causes the input payload to scale linearly with the number of turns, quickly producing massive developer bills.
  • Time-to-First-Token (TTFT): Even without cache, massive context windows take several seconds to ingest. For agentic systems making 20+ sequential tool calls, the execution time multiplies.
  • Attention Degradation: Although Claude supports up to 200,000 tokens, placing crucial instructions or documents inside a massive prompt risks "lost in the middle" attention drops, yielding suboptimal tool selections.

⚙️ Why RAG is Crucial

Retrieval-Augmented Generation (RAG) acts as the filter between a vast document store and the LLM's finite context budget. Rather than passing everything, a vector database index resolves user queries and extracts only the top-k most relevant text chunks.
