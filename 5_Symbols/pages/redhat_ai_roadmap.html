Red Hat Certified Specialist in OpenShift AI

EX267 — Performance-Based Exam

🎯 Prove Your Skills & Knowledge

A Red Hat Certified Developer for OpenShift AI demonstrates hands-on, production-grade ability to install, configure, and operate AI/ML workloads on enterprise Kubernetes infrastructure. This is a performance-based exam — no multiple choice, only real tasks on a live system.

"Candidates must perform tasks on a live Red Hat OpenShift AI environment to prove competency — not theory."
🔗 Official EX267 Exam Page — Red Hat

🧩 9 Core Skill Domains

To earn the EX267, a candidate must be able to perform all of the following on a live Red Hat OpenShift cluster:

🏗️

1. Install Red Hat OpenShift AI (RHOAI)

Set up the RHOAI operator and dashboard on an OpenShift cluster, verify component health.

  • OperatorHub deployment
  • DataScienceCluster resource
  • GPU operator prerequisites
⚙️

2. Configure & Manage RHOAI

Manage platform settings, user access, resource quotas, and RHOAI component lifecycle.

  • Role-based access (RBAC)
  • Component enable/disable
  • Storage configuration
📁

3. Work with Data Science Projects

Create and organise namespaced data science projects that isolate resources per team or use-case.

  • Project creation via dashboard
  • Namespace isolation
  • Resource limits per project
🖥️

4. Use Data Science Workbenches

Launch and configure JupyterLab and other workbench images; manage notebook environments.

  • Custom notebook images
  • PVC-backed persistent storage
  • GPU workbench allocation
🔌

5. Configure Data Connections

Connect workbenches and pipelines to external object storage (S3-compatible), databases, and secrets.

  • S3 / MinIO data connections
  • Secret injection via RHOAI
  • Connection validation
🗂️

6. Use Git to Manage Notebooks Collaboratively

Integrate Git inside JupyterLab for version control, branch management, and collaborative workflows.

  • JupyterLab Git extension
  • Clone / commit / push from UI
  • Reproducible notebook sharing
🤖

7. Work with Machine Learning Models

Train, evaluate, and manage ML models within the platform; track experiments and artefacts.

  • Model registry integration
  • Experiment tracking
  • Model versioning
🚀

8. Deploy Trained Models Using Model Serving

Serve models as REST APIs using single-model and multi-model serving runtimes (KServe, OVMS, Triton).

  • InferenceService (KServe)
  • ModelMesh multi-model serving
  • Endpoint monitoring
🔁

9. Create Data Science Pipelines

Build and run reproducible ML pipelines using Kubeflow Pipelines / Data Science Pipelines Operator.

  • Pipeline authoring (KFP SDK)
  • Scheduled pipeline runs
  • Artifact lineage & logs
